The Full Sensor Sweep (Logging Keys and Nested Data)

In our previous sweep of the database, we successfully retrieved the internal manifest for every vessel. However, there was a major tactical flaw: the computer didn't tell us which ship the data belonged to!

To generate a proper Starfleet report, we need to output the primary identifier alongside the data. By logging both our temporary variable (the Key) and our bracket notation query (the Value) inside the same loop, we can format a completely readable, ship-by-ship manifest. 

let starfleetDatabase = {
    defiant: 
    {
        class: 'escort',
        status: 'docked'
    },

    enterprise:
    {
        class: 'constitution',
        status: 'active' 
    }
};

// Run a full sensor sweep, logging the ship's name AND its data
for (let vessel in starfleetDatabase)
{
    // Print the name of the ship (the Key)
    console.log(vessel);
    
    // Print the ships internal manifest (the Nested Object)
    console.log(starfleetDatabase[vessel]);
}

/*
defiant
Object { class: "escort", status: "docked" }

class: "escort"

status: "docked"

: Object { … }


enterprise
Object { class: "constitution", status: "active" }

class: "constitution"

status: "active"

: Object { … }
*/

Syntax 

for (let key in parentObject) { 
    console.log(key);
    console.log(parentObject[key]); 
}

Return Value

Type: Iteration (Retrieves and pairs both the string identifier and its corresponding child Object sequentially).

Description:

This is the standard procedure for rendering dynamic lists. The for...in loop allows us to execute multiple lines of code during each cycle. First, it grabs the top-level string (let vessel) and prints it to the console, acting as a header. Immediately after, it uses that exact same string inside brackets (starfleetDatabase[vessel]) to unlock the folder and print the contents beneath it. This ensures every piece of data remains perfectly paired with its parent identifier.
