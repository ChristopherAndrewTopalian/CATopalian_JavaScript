Math.asin()

The Math.asin() method stands for "Arcsine." In our game engines, we can think of this as our "Vertical Elevation Decoder." When our local radar detects a target moving above or below our ship's neutral plane, we feed the vertical ratio into this method. It instantly calculates the exact angle we need to pitch our ship up or down to intercept! 

// Tactical radar detects a target moving above our local grid plane.
// The targeting computer provides a vertical height ratio of 0.707.
let verticalRatio = 0.707;

// We ask the computer to decode this ratio into an elevation angle:
let elevationInRadians = Math.asin(verticalRatio);

console.log(elevationInRadians); 
// Result: 0.785398... (Radians are great for the CPU, but bad for the pilot!)

// The Professional Solution: We translate Radians into Degrees!
let elevationInDegrees = elevationInRadians * (180 / Math.PI);

// We use Math.round() to make it a clean, readable number for the UI.
console.log(Math.round(elevationInDegrees));
// Result: 45 (Pitch the ship up exactly 45 degrees to intercept!)

// THE FATAL TRAP: Just like acos(), the input MUST be between -1 and 1!
let brokenSensor = Math.asin(1.5);
console.log(brokenSensor);
// Result: NaN (Sensor failure! Target lost!)

Syntax 

Math.asin(x)

Return Value

Type: Number (The arcsine of the given number, returned in radians between -Pi/2 and Pi/2. Returns NaN if the number is outside the -1 to 1 range.)

Description:

Whenever we build a 3D game or a tracking system, we use a local coordinate grid. The Math.asin() method takes a number representing a vertical ratio (which must be between -1 and 1) and returns the angle of elevation. A positive ratio means the target is above us, and a negative ratio means the target is below us. Because JavaScript calculates angles in Radians, we must always apply our translation formula, multiplying the result by (180 / Math.PI), to convert the data into standard degrees so we can display it clearly on our user interfaces and radar screens!
