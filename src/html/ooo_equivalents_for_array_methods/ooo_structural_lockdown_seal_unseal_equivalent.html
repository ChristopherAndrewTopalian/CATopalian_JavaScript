Object of Objects: Structural Lockdown (The "Seal" Equivalent)

While Object.freeze() places a database under total read-only quarantine, sometimes we only want to lock the architecture of the fleet while still allowing captains to update their ship's status.

By passing our database through Object.seal(), we finalize the registry. No new vessels can be added, and no existing vessels can be deleted. However, unlike a freeze, the nested data inside the existing ships remains completely editable. Just like freezing, there is no "unseal" command, to restructure the fleet, we must clone it into a brand new Object using the Spread Syntax (...). 

let tacticalDatabase = {
    enterprise: 
    { 
        class: 'constitution', 
        shields: 'offline' 
    },
    defiant: 
    { 
        class: 'escort', 
        shields: 'offline' 
    }
};

// 1. We seal the architecture of the database
Object.seal(tacticalDatabase);

// 2. We attempt to add a new ship (This FAILS silently)
tacticalDatabase.voyager = { class: 'intrepid', shields: 'offline' };

// 3. We attempt to delete a ship (This FAILS silently)
delete tacticalDatabase.enterprise;

// 4. We attempt to modify existing data (This SUCCEEDS!)
tacticalDatabase.defiant.shields = 'maximum';

console.log(tacticalDatabase);
/*
Result:
Object { enterprise: {…}, defiant: {…} }

enterprise: Object { class: "constitution", shields: "offline" }
defiant: Object { class: "escort", shields: "maximum" }
// Notice Voyager was not added, and Enterprise was not deleted!
*/

Syntax 

// To Seal:
Object.seal(parentObject);

// To "Unseal" (Clone):
let newObject = { ...parentObject };

Return Value

Type: Object. Object.seal() returns the exact same object that was passed into it, but alters its internal permissions to prevent structural additions or deletions.

Description:

Object.seal() is the perfect tool for standardizing user interfaces and data forms. If you have a strict template that expects exactly three properties, sealing the Object prevents rogue code from accidentally injecting a fourth property or deleting a necessary one, which could crash the viewscreen. It enforces a rigid database schema while allowing the living data inside to update normally.
