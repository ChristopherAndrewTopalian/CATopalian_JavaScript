Object of Objects: Removing Entries (The "Pop" Equivalent)

When operating an Array, we use pop() to remove whatever item happens to sit at the very end of our sequence. But because a multidimensional Object has no "end" and no numbered order, we cannot simply pop the last item.

Instead, we are granted absolute precision. To decommission a vessel and remove it from our active registry, we use the delete operator. This allows us to surgically target a specific Key by its exact name and wipe both the Key and its nested manifest from the memory banks instantly. Let's decommission the original Enterprise. 

let starfleetDatabase = {
    enterprise: 
    {
        class: 'constitution',
        status: 'active' 
    },

    defiant: 
    {
        class: 'escort',
        status: 'docked'
    },

    voyager: 
    {
        class: 'intrepid',
        status: 'deployed'
    }
};

// Removing an entry using the delete operator and Dot Notation
delete starfleetDatabase.enterprise;

// Removing an entry using Bracket Notation
delete starfleetDatabase['defiant'];

console.log(starfleetDatabase);

/*
Object { voyager: {…} }

voyager: Object { class: "intrepid", status: "deployed" }

: Object { … }
*/

Syntax 

delete parentObject.targetKey;

delete parentObject['targetKey'];

Return Value

Type: Boolean. Returns true if the removal was successful (or if the Key didn't exist in the first place), and false only if the property was mathematically locked and could not be deleted. The parent Object is permanently mutated.

Description:

The delete operator is our surgical tool for data management. While an Array forces us to manipulate the front or back of a line, the delete operator allows us to instantly eradicate a Key-Value pair from anywhere within the database architecture. This completely frees up the memory that the nested Object was utilizing. We can use Dot Notation for static, known names, or Bracket Notation when we want to use dynamic variables to decide which ship to decommission.
