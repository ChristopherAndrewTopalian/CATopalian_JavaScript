Object of Objects: Internal Duplication (The "copyWithin" Equivalent)

When operating an Array, we use copyWithin() to take existing data from one position and overwrite another position inside the exact same list.

In a multidimensional Object, we replicate this behavior by duplicating the data from a source Key into a target Key. However, because our vessels are nested Objects, simply using the equals sign (=) will only create a linked reference. To safely duplicate a vessel so that it operates independently, we must use the modern structuredClone() command to perfectly replicate the ship's architecture before assigning it to its new registry name. 

let starfleetDatabase = {
    defiant: 
    {
        class: 'escort',
        status: 'docked'
    },

    sao_paulo: 
    {
        class: 'unknown',
        status: 'under construction'
    }
};

// We take the exact specs of the Defiant, create a true physical clone of the data, 
// and use it to overwrite the Sao Paulos registry entry.
starfleetDatabase.sao_paulo = structuredClone(starfleetDatabase.defiant);

// To prove they are independent, we change the Sao Paulos status:
starfleetDatabase.sao_paulo.status = 'active deployment';

console.log("Original Defiant:", starfleetDatabase.defiant);
console.log("Cloned Sao Paulo:", starfleetDatabase.sao_paulo);

/*
Original Defiant: 
Object { class: "escort", status: "docked" }

Cloned Sao Paulo: 
Object { class: "escort", status: "active deployment" }
*/

Syntax 

parentObject.targetKey = structuredClone(parentObject.sourceKey);

Return Value

Type: None (Assignment Operation). The assignment operation itself mutates the parent Object by either creating a brand new Key or permanently overwriting an existing one with the cloned data.

Description:

True internal duplication requires precision memory management. If we write target = source, JavaScript merely points two names at the exact same memory address. By utilizing structuredClone(), we force the JavaScript engine to perform a "Deep Copy", physically unpacking every nested property of the source vessel and rebuilding a mathematically perfect, yet totally disconnected, replica at a new memory address. This allows us to overwrite existing database slots (just like copyWithin) without risking data contamination between the two vessels.
