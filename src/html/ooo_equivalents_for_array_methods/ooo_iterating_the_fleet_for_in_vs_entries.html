Object of Objects: Iterating the Fleet (for...in vs entries)

Before modern JavaScript, the only way to loop through a multidimensional Object was the for...in loop.

However, this legacy loop has a fatal flaw: it doesn't just read our active registry. It also sweeps up "ghost signals", properties inherited from the Object's Prototype chain. To prevent these ghosts from crashing the interface, developers had to manually inject a security scan inside every loop. Today, we bypass this danger entirely by using Object.entries(), which automatically filters out the ghosts and only iterates over our genuine, physical data. 

// Example 1: The ES5 Legacy Method (The for...in Loop)

let starfleetDatabase = {
    enterprise: { class: 'constitution' },
    defiant: { class: 'escort' }
};

// We iterate through the registry, but we MUST include a manual security scan!
for (let shipName in starfleetDatabase) 
{
    // If we forget this line, the loop might process inherited garbage data!
    if (Object.hasOwn(starfleetDatabase, shipName)) 
    {
        console.log("Legacy Scan Verified: " + shipName.toUpperCase());
    }
}

/*
Legacy Scan Verified: ENTERPRISE
Legacy Scan Verified: DEFIANT
*/

// Example 2: The Modern Standard (Object.entries)

let starfleetDatabase = {
    enterprise: { class: 'constitution' },
    defiant: { class: 'escort' }
};

// Object.entries() automatically ignores inherited prototype data.
// We get a clean, secure loop with built-in Destructuring!
for (let [shipName, specs] of Object.entries(starfleetDatabase)) 
{
    console.log("Modern Scan Verified: " + shipName.toUpperCase() + " (" + specs.class + ")");
}

/*
Modern Scan Verified: ENTERPRISE (constitution)
Modern Scan Verified: DEFIANT (escort)
*/

Syntax (Legacy ES5) 

for (let keyName in parentObject) {
    if (Object.hasOwn(parentObject, keyName)) { ... }
}

Syntax (Modern Standard) 

for (let [keyName, nestedData] of Object.entries(parentObject)) { ... }

Return Value

Type: None (Iteration). Both methods simply execute commands in a loop until they run out of vessels to process. They do not return new Arrays or Objects unless you specifically push data to an external variable.

Description:

Teaching the legacy for...in loop is a critical right of passage for every cadet, as they will encounter it in thousands of older codebase registries. It exposes exactly why modern JavaScript engines evolved. By moving to Object.entries(), we eliminate the need for manual security checks, we guarantee that our vessels are iterated in the exact chronological order they were inserted, and we gain the ability to instantly destructure our nested data, resulting in dramatically cleaner and safer code.
