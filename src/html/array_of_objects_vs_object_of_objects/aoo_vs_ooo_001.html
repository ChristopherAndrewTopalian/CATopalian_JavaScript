The Sensor Sweep vs. The Direct Comm-Link

Welcome to Advanced Database Architecture. Up until now, you have managed fleets using an Array of Objects. Arrays are excellent for ordered lists, but they have a major tactical flaw: finding a specific ship requires scanning the entire fleet one by one.

To achieve maximum engine performance in a simulation, we upgrade our database to an Object of Objects. Instead of placing ships in a numbered list, we assign each ship a unique Key (its name). This gives us a direct comm-link to the vessel, bypassing the need for a sensor sweep entirely. Let's look at how we retrieve the Defiant using both methods.

Method 1: Array of Objects (The Linear Sweep)

In an Array, the computer does not know where the Defiant is. We must use a loop or the .find() command to check every single ship until we get a match. If the fleet has 10,000 ships, this takes processing power. 

// The Array of Objects (A List)
let arrayFleet = [
    { name: 'Enterprise', class: 'Constitution', shields: 100 },
    { name: 'Defiant', class: 'Escort', shields: 100 },
    { name: 'Voyager', class: 'Intrepid', shields: 100 }
];

// We must sweep the array to find the Defiant
let targetShip = arrayFleet.find(function(ship) {
    return ship.name === 'Defiant';
});

console.log(targetShip.class);

/*
Escort
*/

Method 2: Object of Objects (The Direct Comm-Link)

In an Object of Objects, the ship's name acts as a permanent, unique memory coordinate. We do not need to sweep the database. We simply type the name of the ship, and the engine connects instantly. 

// The Object of Objects (A Dictionary)
let objectFleet = {
    enterprise: { class: 'Constitution', shields: 100 },
    defiant: { class: 'Escort', shields: 100 },
    voyager: { class: 'Intrepid', shields: 100 }
};

// Instant retrieval using Dot Notation (No loops required!)
let targetShip = objectFleet.defiant;

console.log(targetShip.class);

/*
Escort
*/

Engine Performance Summary

This is the secret to high-speed game design. Searching an Array of Objects has a performance cost of O(N), meaning the larger the fleet gets, the longer the scan takes. Retrieving data from an Object of Objects has a performance cost of O(1). Whether you have 3 ships or 3,000,000 ships in the registry, the engine retrieves the target ship in the exact same fraction of a millisecond.
