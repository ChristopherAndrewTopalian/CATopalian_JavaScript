AOO filterByYearMonth()

Filtering by a single metric is useful, but what if our database has logs spanning multiple years? If we just search for "February," we will pull up February logs from 2024, 2025, and 2026 all at once! To perform a precision sweep, we must check both the Year AND the Month simultaneously. By using the JavaScript Logical AND operator (&&) inside our .filter() method, we can demand that two completely separate conditions are met before a log is approved for extraction. 

// A standard Array of Objects (AOO) containing ship logs across multiple years
let shipLogs = [
    { mission: "Maiden Voyage", date: "2024/02/05" },
    { mission: "Routine Patrol", date: "2025/02/15" },
    { mission: "Diplomatic Transport", date: "2026/02/08" },
    { mission: "Warp Core Refit", date: "2026/02/24" },
    { mission: "Nebula Survey", date: "2026/03/10" }
];

let targetYear = "2026";
let targetMonth = "02"; 

// THE OLD WAY (Manual Sensor Sweep)
function filterByYearMonthManual(whichArray, whichYear, whichMonth) {
    let result = [];
    for (let z = 0; z < whichArray.length; z++) {
        // Chop the date string into 3 pieces: ["2026", "02", "08"]
        let parts = whichArray[z].date.split('/');

        // We use the Logical AND (&&) to ensure BOTH parts match!
        if (parts[0] === whichYear && parts[1] === whichMonth) {
            result.push(whichArray[z]);
        }
    }
    return result;
}

// THE MODERN WAY (Reusable Automated Function)
function filterByYearMonth(whichArray, whichYear, whichMonth) {
    return whichArray.filter(function(item) {
        let parts = item.date.split('/');
        
        // If the Year matches AND the Month matches, the item is kept!
        return parts[0] === whichYear && parts[1] === whichMonth; 
    });
}

let precisionLogs = filterByYearMonth(shipLogs, targetYear, targetMonth);
console.log(precisionLogs); 
// Result: We ONLY get the two February logs from 2026! 
// The 2024 and 2025 February logs are safely ignored.

Direct Filtering (On The Fly!)

We can harness this compound logic right in the middle of our code without writing a separate function. Suppose Starfleet Command asks us to instantly generate a list of all vessels that docked at Earth Spacedock during the holiday season of December 2025. We can chop the string, apply the double condition, and save it straight to a variable! 

// A database of fleet movements
let fleetMovements = [
    { ship: "USS Hood", location: "Earth", date: "2025/11/28" },
    { ship: "USS Enterprise", location: "Earth", date: "2025/12/15" },
    { ship: "USS Defiant", location: "Deep Space 9", date: "2025/12/22" },
    { ship: "USS Voyager", location: "Earth", date: "2025/12/24" },
    { ship: "USS Titan", location: "Earth", date: "2026/01/05" }
];

// Filter inline to find only Earth dockings in December (12) of 2025
let holidayDockings = fleetMovements.filter(function(movement) {
    let parts = movement.date.split('/');
    return movement.location === "Earth" && parts[0] === "2025" && parts[1] === "12";
});

console.log(holidayDockings);
// We immediately extract the Enterprise and Voyager! 
// (The Defiant is ignored because it was at DS9, and the Titan arrived too late in 2026).

Syntax 

function filterByYearMonth(whichArray, whichYear, whichMonth)

Return Value

Type: Array (A new array of objects containing only the records that occurred during the specific month of the specific year requested.)

Description:

This advanced filter utilizes the exact same .split('/') string manipulation as our previous tutorial, but introduces compound logic. The double-ampersand symbol (&&) acts as a strict gateway. The JavaScript engine checks the left side of the gateway (does the year match?). If that is false, it instantly discards the item and moves on to save time. If it is true, it then checks the right side of the gateway (does the month match?). An item is only passed into the brand new array if it can successfully pass both tests. (We can even chain three conditions together, as seen in the Direct Filtering example!)
