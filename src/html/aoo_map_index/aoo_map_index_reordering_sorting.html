Array of Objects: Reordering and Sorting

In any large application, we inevitably need to sort our data. We might need to render a UI leaderboard, organize ships by tactical priority, or alphabetize our registry. We know that Array.prototype.sort() physically shuffles the rows in our Spreadsheet.

This raises a critical question: If we shuffle the rows in our Array, does it break our Map index? Do we have to rebuild the entire Map every time we sort the Array?

Because of the magic of Memory References we learned in the last tutorial, the answer is no. The Map does not store the Array's row number; it holds a direct tether to the Object itself. We can shuffle the Array as much as we want, and our 0ms Map lookup will never fail. 

// Example 1: Sorting the Master Array

var fleetArray = [
    { id: 'voyager', class: 'intrepid', priority: 3 },
    { id: 'enterprise', class: 'constitution', priority: 1 },
    { id: 'defiant', class: 'escort', priority: 2 }
];

var fleetIndex = new Map();

// Build the index ONCE
for (var i = 0; i < fleetArray.length; i++) {
    fleetIndex.set(fleetArray[i].id, fleetArray[i]);
}

console.log("Before Sort - Row 0:", fleetArray[0].id); // Output: voyager

// Sort the Array by Tactical Priority (Lowest number first)
fleetArray.sort(function(a, b) {
    return a.priority - b.priority;
});

console.log("After Sort - Row 0:", fleetArray[0].id);  // Output: enterprise
console.log("After Sort - Row 2:", fleetArray[2].id);  // Output: voyager

// Example 2: The Magic Lookup Test

// Our Array has been completely shuffled. 'voyager' was moved from 
// Row 0 all the way to Row 2. Let us see if the Map still knows where it is.

var targetShip = fleetIndex.get('voyager');

console.log("Map found ship:", targetShip.id);
/*
Map found ship: voyager
*/

console.log("Map found priority:", targetShip.priority);
/*
Map found priority: 3
*/

// Proving they are still connected:
// If we update the target via the Map, the sorted Array still updates!
targetShip.priority = 99;

console.log("Sorted Array updated:", fleetArray[2].priority);
/*
Sorted Array updated: 99
*/

Performance & Architecture

Array Sort Speed: O(N log N). Sorting takes processing power, which is why we want to do it using JavaScript's highly optimized built-in Array methods rather than writing manual loops.

Map Lookup Speed: O(1). The lookup remains perfectly instant, regardless of how the Array is sorted.

Description:

This tutorial proves the ultimate superiority of the Indexed Array Pattern over raw Objects. If we were using an "Object of Objects," sorting would require us to extract the keys into a 2D Array, sort them, and then reconstruct an entirely new Object from scratch. By using our hybrid pattern, we just run fleetArray.sort() and walk away. The Array handles the UI rendering sequence, and the Map Index silently maintains perfect 0ms targeting lock on every entity.
