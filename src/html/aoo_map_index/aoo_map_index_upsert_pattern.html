Array of Objects: The Upsert Pattern (Find or Create)

In a live game engine or an active Artificial Intelligence, data is constantly streaming in. When our radar detects a ship, we have to make a split-second decision: Do we already know about this ship, or is this a brand new contact?

If it is an existing ship, we need to Update its coordinates. If it is a new ship, we need to Insert it into our database. In computer science, combining these two actions is called an Upsert.

Without our Map Index, an Upsert forces the CPU to search the entire Array row-by-row for every single incoming radar blip. With our Indexed Array Pattern, we can perform thousands of Upserts per second instantly. 

// Example 1: The Functional Upsert

let fleetArray = [];
let fleetIndex = new Map();

// A reusable function to handle incoming radar data
function upsertShip(incomingData) {
    // Instant 0ms Lookup: Does this ship exist?
    let existingShip = fleetIndex.get(incomingData.id);

    if (existingShip) {
        // UPDATE (It exists!)
        // Because of memory references, updating this variable
        // automatically updates the ship inside the master Array.
        existingShip.x = incomingData.x;
        existingShip.y = incomingData.y;
        existingShip.shields = incomingData.shields;
        console.log("Updated existing ship:", incomingData.id);
    } else {
        // INSERT (It is brand new!)
        // We add the new object to both our Spreadsheet and our Card Catalog.
        fleetArray.push(incomingData);
        fleetIndex.set(incomingData.id, incomingData);
        console.log("Inserted new ship:", incomingData.id);
    }
}

// SIMULATION: Incoming Radar Data

// Radar detects a new ship. (Triggers Insert)
upsertShip({ id: 'defiant', x: 100, y: 200, shields: 100 });

// Radar detects the same ship moving. (Triggers Update)
upsertShip({ id: 'defiant', x: 150, y: 250, shields: 90 });

// Radar detects a second ship. (Triggers Insert)
upsertShip({ id: 'voyager', x: 500, y: 500, shields: 100 });

console.log("Total Ships in Array:", fleetArray.length); 
/*
Output:
Inserted new ship: defiant
Updated existing ship: defiant
Inserted new ship: voyager
Total Ships in Array: 2
*/

// Example 2: Upgrading our FleetManager Class

// We can add this superpower directly to the Class we built in Tutorial 4.
// Now, the rest of our game code never has to worry about the logic!

class FleetManager {
    constructor() {
        this.list = [];
        this.index = new Map();
    }

    upsert(data) {
        let existing = this.index.get(data.id);
        
        if (existing) {
            // Update the physical properties dynamically
            // (Using Object.assign is a quick way to merge new data)
            Object.assign(existing, data);
        } else {
            // Insert
            this.list.push(data);
            this.index.set(data.id, data);
        }
    }
    
    get spreadsheet() {
        return this.list;
    }
}

let starfleet = new FleetManager();
starfleet.upsert({ id: 'enterprise', status: 'docked' }); // Inserts
starfleet.upsert({ id: 'enterprise', status: 'warp' });   // Updates

Performance & Architecture

Upsert Speed: O(1). Because we route the existence check through the Map Index rather than Array.find(), the engine determines whether to Update or Insert instantaneously, regardless of how large the database grows.

Description:

The Upsert is the beating heart of game loops and AI sensory input. It allows the system to blindly accept massive streams of incoming data without micromanaging existence checks. By pairing the Upsert logic with our Map Index's memory references, we guarantee that our permanent Array reflects reality in real-time, with virtually zero cost to the CPU.
